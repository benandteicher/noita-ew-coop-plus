# Ping+ R15 targeting/catalogue implementation

`identification.lua`, `vanilla_catalogue.lua`, and `world_target.lua` are the Worker A production files. The coordinator owns `player_ping.lua` integration and all native sessions. This document describes source/getter tests; coordinator native results supersede or qualify it separately.

## Native source findings

The installed `data.wak` SHA256 is `c95a0c01a55ec29267afef6bbec8a0cae0ba2b350638e2203674ed4dfb9227c3`. `scripts/generate_ping_vanilla_catalogue.py` reads its XML/PNG headers, native perk-list literal metadata, and installed English translation CSV without executing game Lua. It produces 173 enemy identities across 300 native animal paths, 90 supported native item paths, 60 ordinary item identities, 115 loose-perk identities, and 2,853 native image sizes. Existing heart/refresher animated art, chest art, spell source parser and three-field network identity format remain.

The native enemy catalogue includes ordinary ground/flying/physics-driven animals and other vanilla body implementations. Runtime classification requires a known native path/name or a unique native name/body signature, enemy tag, DamageModel and a displayed body, not AnimalAI. This matters because `ewext/src/modules/entity_sync/diff_model.rs::init_remote_entity` removes PhysicsAI/AdvancedFishAI and usually AnimalAI/AIAttack on remote reconstruction. Native reconstruction preserves name/body and damage identity, but actual remote ground/flying roots may have an empty filename. The catalogue includes 206 unique native name/primary-body signatures across 156 names for this case; emitted/shared additive overlays are excluded. Runtime fallback requires both an exact native name and a displayed matching body image, never a name alone, and nonempty unknown/mod paths remain rejected. Same-name variants such as native zombie/weak-zombie images normalize to their shared vanilla identity. Item reconstruction uses native filename or serialized entities; vanilla physical items are not rejected merely for having ProjectileComponent. Native potions, sacks and tablets have that collision component; tablets also lack `item_pickup` and use `tablet`. A uniquely matched native ItemComponent icon/name signature handles absent serialized filenames. Tablets normalize to a generic Emerald tablet without inspecting book text. Wands use their world-root/wand/ItemComponent/Ability structure, not filename or a perfect ray.

Metadata is local and bounded. Unknown categories, extra payload keys, unknown IDs, names/paths provided by packets and mod paths are not accepted as identities. No entity creation, setter, ownership/physics change, inventory traversal, action/perk function execution, material-content read, progression lookup or unlock is added. Loose perks use `item/perk_ID` and native perk_id VariableStorage; their normal local name/icon/description comes from literals. Owned HUD perks require separate coordinator investigation.

## Selector interface

- `world_target.target(x,y,view,previous_entity?)` returns a selection table or nil/reason. Selection fields: `entity,x,y,kind,ident?,boxes,bounds`. `bounds` is `{min_x,min_y,max_x,max_y}`; `boxes` contains rotated center/half-extents plus AABB. `kind` is `wand`, `spell`, `item` or `enemy`. No wand snapshot is taken.
- `capture(entity,view)` returns a fresh selection or nil/reason. It checks current root, enabled pickable ItemComponent for items, native identity, displayed geometry, viewport intersection and loaded body. Enemies require a clear ray to one of five displayed-body points. Items have no player-origin ray requirement.
- `revalidate(selection,x,y,view)` repeats capture and pointer distance at activation. Inventory parenting, disabled/unpickable items, death, motion away from the pointer or identity changes reject the selection.
- `draw_hint(gui,selection,view)` draws eight faint short corner strokes, no label/panel. The adapter chooses whether it is appropriate to display. Hint geometry and activation use the same selector.
- Legacy `identification.capture/target` delegate to this same module; `identification.inspect` only classifies the current loose world root.

Candidates are enumerated around the camera using native wand/item/pickup/card/tablet/perk/enemy tags and a 256-world-pixel guard beyond its diagonal. Bounds, not distance to the root, determine the pointer hit. The candidate/tag counts, geometry dimensions, metadata and XML cache are bounded. Any over-limit tag list fails closed. Cheap geometry is ranked first; only pointer-relevant candidates receive final metadata/loaded-body/occlusion checks, capped at 16 candidates and five enemy rays per candidate. Exact displayed-body hits beat assistance. A 3px margin and assistance up to 7 world pixels use nearest oriented rectangle distance. Overlapping direct objects prefer smaller displayed body, then centrality, then stable entity ID; small same-tier prior-target retention reduces jitter. Unknown directly hit loose objects with available native geometry block assisted neighbours. Custom mod images without catalogue/frame geometry remain unsupported.

World sprites use native PNG sizes or bounded XML animation frames, component transforms and sprite pivot/scale. Native overlays established that a nonzero component pivot overrides XML; zero component pivots fall back to authored XML pivots. These are not added together. Physical shapes use their image pivot and matching **enabled** PhysicsBody's actual converted transform. Segmented sprites with manually positioned segments do not expose those segment transforms to Lua; a native worm/dragon root hitbox is the limited fallback, not invented full-tail tracking. Enemy packets still contain only the static spotted position; this module does no ongoing marker tracking. Exact light/fog matching remains deferred.

## Focused checks

`python -m unittest discover -s tests -p test_ping_targeting_r15.py -v` exercises actual installed XML/metadata for ground/flying/physics enemies with EW's remote AI removals, actual-native empty-filename body signatures and signed facing flips, native potion variants/sacks/tablets/throwables, loose perks and working pickups/spells, rotated long native wand artwork, direct-vs-assisted ordering, deterministic ties, margins, pickup/movement revalidation and loaded/camera/unknown fallbacks. These are getter fixtures populated from stock XML, not running game-session evidence.

The R12 identification tests were retained and updated for the new contract: item rays/tiny origin radius/tie-to-location behavior are deliberately replaced by body bounds, item terrain tolerance and deterministic selection. Their plain-packet/local-resolution/read-only/unknown/inventory checks remain. The R13 artwork regressions retain accepted full animated hearts/refresher and local metadata behavior. Coordinator performs the integrated suite once and records the actual native matrix, previews and limits.
